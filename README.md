# 다감노📸 소모임 분석

[소모임](https://www.somoim.co.kr) **다감노** 모임의 게시글·사진·멤버를 구글 스프레드시트에 쌓아 두고 출사·사진·테마 활동·참석 추적 인사이트를 보여주는 Streamlit 웹 앱입니다. **보정은 시트에서 한 번만** 하면 이후 수집에도 계속 적용됩니다.

## 구조 — 세 가지를 분리한다

```
   [somoim API]  ─ 기간 지정 수집 (YYYYMM ~ YYYYMM, 다년 가능)
        │
        ▼
   📗 다감노_raw    ← 앱이 쓴다 (게시글 id 기준 upsert)
        │              게시글 · 사진 · 멤버 · 강퇴멤버 · 가입인사매핑 · _수집이력 · _원본필드
        │  분석 시 병합
        ▼
   📕 다감노_보정   ← 사람이 쓴다 (앱은 읽기 + 없는 항목만 추가)
        │              이름매핑1 · 후기이름매핑 · 공지보정 · 참석자보정 · 테마사진보정
        ▼
   5개 탭 인사이트
```

**핵심 규칙: 수집은 보정 시트의 기존 값을 절대 건드리지 않습니다.** 보정은 게시글 id와 이름 토큰이라는 안정적인 키에 매달리므로, 다시 수집하든 완전히 다른 기간을 받아오든 그대로 따라붙습니다. 예전처럼 엑셀을 받아 두었다가 다시 올릴 필요가 없습니다.

- **가입인사 수집은 cat=J 서버 필터** + 활성 멤버 mid 기반 조기 종료로 그룹 시작까지 거슬러 가도 빠릅니다.
- **활성/탈퇴 구분은 user id(`wid`↔`mid`) 기준** — 닉네임 일치가 아니라 user id로 매칭해 동명이인·닉네임 변경에도 흔들리지 않습니다.
- **작성자 랭킹은 활성 멤버만** 집계하지만, **탈퇴 멤버가 연 출사 후기의 참석자 추적은 그대로 유지**됩니다.

## 사용법

1. **비밀번호 입력** — 배포 앱은 관리자만 쓰도록 최초 화면에서 막습니다.
2. **사이드바 → 📥 수집** — 시작 년/월 ~ 종료 년/월을 고르고 **수집 시작**.
   - 한 해 전체는 `2026-01 ~ 2026-12`, 한 달만 보려면 시작·종료를 같게.
   - 활동 시즌처럼 **해를 넘기는 구간**(`2025-09 ~ 2026-03`)도 그대로 지정할 수 있습니다.
   - 이미 받아 둔 글은 최신 내용으로 갱신되고, 기간이 겹쳐도 중복되지 않습니다.
3. **📕 보정 시트에서 빈칸 채우기** — 수집이 끝나면 앱이 보정이 필요한 항목을 시트에 자동으로 채워 넣습니다. 사이드바의 **보정 시트 열기**로 이동해 값만 적으면 됩니다.

   | 탭 | 채우는 것 |
   |---|---|
   | **① `이름매핑1`** | **여기부터.** 멤버의 실명. 앱은 닉네임만 알고 실명을 모르는데, 후기 본문에는 실명이 더 자주 나옵니다. |
   | ② `후기이름매핑` | ①로도 안 풀린 나머지 → 마스터 닉네임 / `__LEFT__`(탈퇴·강퇴) / `__NOISE__`(이름 아님). `탈퇴`·`강퇴`·`노이즈`·`❌` 같은 한글 표기도 받습니다. |
   | ③ `공지보정` | 출사일·카테고리를 자동으로 못 알아낸 공지. 취소 여부와 분석 제외도 여기서. 어느 카테고리에도 안 걸리는 전체 공지는 **`일반공지`** 로 지정하면 출사 집계에서 빠집니다. |
   | ④ `참석자보정` | 참석자를 뽑지 못한 후기 **+ 본문이 잘린 후기** → 이름을 쉼표로 구분해 입력. 앱이 뽑은 명단·본문 길이·잘림 여부가 참고 열에 미리 채워집니다. |
   | ⑤ `테마사진보정` | 댓글이 달렸지만 테마사진이 아닌 사진. **앱에서 사진을 보며 체크**하면 여기 기록됩니다(손으로 채울 필요 없음). |

   **`이름매핑1`을 먼저 채우면 ②의 양이 크게 줄어듭니다.** 실명으로 풀리는 이름이 자동으로 걸러져, ②에는 오타·나간 멤버·이름이 아닌 것만 남습니다.

   - 전 멤버가 **닉네임 순**으로 깔려 있어 갖고 계신 명단을 `실명` 열에 통째로 붙여넣을 수 있습니다.
   - 가입인사에서 찾아낸 실명은 **미리 채워져** 있습니다.
   - 키는 `멤버 id`라 **닉네임이 바뀌어도 실명이 따라갑니다.** 이 열은 고치지 마세요.
   - 실명을 채우면 분석 결과에 `원석사진(정원석)`처럼 병기됩니다.

   빈칸으로 두면 "아직 보정 안 함"으로 보고 넘어갑니다. 실수로 지워도 원래 데이터가 날아가지 않습니다.

   **시트 안에 설명이 들어 있습니다** — 이 표를 외울 필요는 없습니다.

   - **`_사용법` 탭** — 전체 규칙과 각 칸에 넣을 값.
   - **헤더 칸 메모** — 열 이름에 마우스를 올리면 그 칸 설명이 뜹니다.
   - **드롭다운** — `처리`·`카테고리`·`취소`·`제외`는 목록에서 고릅니다. 목록에 없는 새 닉네임도 직접 입력할 수 있습니다(경고만 뜹니다).

   드롭다운의 닉네임 목록은 **수집할 때마다 최신 멤버 명단으로 갱신**됩니다.
   안내를 갱신해도 이미 적어 두신 값은 건드리지 않습니다.

   | 칸 | 넣는 값 |
   |---|---|
   | `후기이름매핑` · 처리 | 마스터 닉네임 / `__LEFT__` / `__NOISE__` |
   | `공지보정` · 카테고리 | `인물` `인물&풍경` `풍경` `GN` `보정` `문화` `일반공지` |
   | `공지보정` · 출사일 | `YYYY-MM-DD` — 공지 작성일이 아니라 **실제 출사한 날** |
   | `공지보정` · 취소 / 제외 | `TRUE` / `FALSE` |
   | `참석자보정` · 참석자 | 쉼표로 구분한 닉네임. 뽑아낸 결과를 **통째로 대체**하므로 작성자도 참석했다면 함께 적습니다. 오른쪽 `추출된 참석자`가 맞으면 그대로 복사해 넣으세요 — 빈칸은 끝까지 "아직 안 봄"입니다 |

   첫 열(`공지 id`·`후기 id`·`이름토큰`)이 보정을 붙이는 열쇠입니다. 이 값을 고치면 보정이 다른 글에 붙거나 사라집니다.
4. **🔄 새로고침** — 시트에서 고친 내용이 분석에 반영됩니다.
5. **결과 확인** — 5개 탭. 개요 맨 위 **🎯 신뢰도 패널**로 무엇이 덜 채워졌는지 먼저 확인하세요.

앱을 다시 열면 **수집 없이 곧바로 저장된 데이터로 분석 결과가 뜹니다.**

> **🎯 신뢰도 패널이 결과 화면의 맨 앞에 있습니다.** 본문이 잘려 들어오는 탓에 참석자가 비어 보일 수 있는데, **진짜 없는 것과 아직 안 채운 것을 구분할 수 없으면 결과를 잘못 읽게 됩니다.** 건수는 보정 시트의 미기입 행 수를 그대로 쓰므로 화면과 시트가 어긋나지 않습니다.
>
> **🎨 테마사진은 화면에서 바로 고칩니다.** 댓글이 달렸다고 다 테마사진은 아니므로, 사진을 보고 **테마 아님**에 체크한 뒤 **변경 저장**을 누르면 제출 인원·참여자·테마사진 수가 즉시 갱신되고 `테마사진보정` 시트에 남습니다. 잘못 눌렀으면 접힌 목록에서 되돌릴 수 있습니다.
>
> 체크박스는 **사진과 같은 테두리 칸 안, 사진 바로 아래**에 있어 어느 사진에 대한 체크인지 헷갈리지 않습니다. 이 구역은 Streamlit **프래그먼트**라 체크할 때 이 구역만 다시 그리고, 월 목록은 **상태를 갖는 expander**라 펼쳐 둔 달이 그대로 열려 있습니다. 앱 전체를 다시 그리는 것은 **변경 저장·되돌리기** 두 번뿐이라 여러 장을 이어서 고를 수 있습니다. 닫힌 달은 아예 그리지 않아 사진이 많아도 가볍습니다.
>
> 원본 데이터는 앱에서 다시 그리지 않습니다 — 사이드바의 **📗 raw 시트 열기**로 구글 시트에서 정렬·필터·다운로드하세요.

## 분석 엑셀 (출력 전용) — 지금은 숨김

> ⚠️ **내보내기 버튼을 잠시 숨겨 두었습니다** (`streamlit_app.py`의 `SHOW_EXPORT`). 엑셀이 화면과 어긋났기 때문입니다 — 없어진 `👤 사용자` 시트가 그대로 있고, 신뢰도·함께 간 사람·정착률 같은 새 통계는 빠져 있습니다. **화면과 다른 결과 파일을 내보내면 어느 쪽이 맞는지 알 수 없게 됩니다.** 맞춘 뒤 `SHOW_EXPORT = True`로 되살립니다. 아래는 숨기기 전 기준입니다.

가시 시트 12개 (+ 멤버 정보 있으면 13개) — UI 인사이트를 그대로 옮긴 결과:

1. **📊 대시보드** — KPI 6장 + 월별 활동 표 + 진행/취소 클러스터드 바 차트
2. **👤 게시글 통계** — 작성자별 공지/취소/후기/카테고리별/좋아요/취소율 + 데이터바
3. **📌 출사 공지** — 공지 전체 목록 (취소·진행 색상 구분)
4. **📝 후기글** — 후기 전체 목록
5. **📷 사진** — 사진 전체 목록 (테마사진 색상 강조)
6. **🎨 월별 테마 매트릭스** — 작성자 × 월
7. **👤 사진 통계** — 작성자별 사진 수·테마 비율·좋아요
8. **🏷️ 카테고리** — 카테고리 × (공지 수·진행·취소·좋아요 합) + 데이터바, 이어서 **카테고리 × 월** 블록
9. **💡 인사이트** — ① 활동 규모, ② 핵심 기여자 TOP 3, ③ 사진 TOP 5, ④ 테마 패턴, ⑤ 카테고리 트렌드, ⑥ 취소율 분석
10. **🎯 출사별 참석자** — UI 👥 참석 탭과 동일: 공지 제목/후기 제목 분리, `✓ 매칭` / `⚠️ 후기 없음` 상태, 취소 제외 + **고아 후기 섹션** (공지 매칭 안 된 후기)
11. **👥 멤버별 참석** — 멤버 × 카테고리 매트릭스 + 데이터바
12. **📅 월별 참석 매트릭스** — 멤버 × 월 (참석=▣)
13. **🧑‍🤝‍🧑 멤버 현황** — 활성/휴면/유령 분류, 동명이인 ⚠️ 마킹 (members 수집 시)

> 엑셀은 **보고 공유하는 결과물**일 뿐입니다. 원본과 보정은 구글 시트에 있으므로 이 파일을 보관했다가 다시 올릴 필요가 없습니다. 구글 시트로 내보내기도 이 엑셀을 Drive가 변환하는 방식이라 내용이 같습니다.

### 코드로 직접 (선택)

```python
from core import (
    collect_posts, collect_photos,
    collect_members, collect_banned_names,
    collect_join_greetings, parse_join_name_aliases,
    annotate_attendees, match_outings_with_reviews,
    save_excel,
)

start_ym, end_ym = 202509, 202603   # 해를 넘겨도 됨. 한 달만: 202605, 202605
posts  = collect_posts(start_ym, end_ym)
photos = collect_photos(start_ym, end_ym)
members, master = collect_members()
banned = collect_banned_names()

# cat=J 서버 필터 + 활성 멤버 mid 기반 조기 종료
min_joined = min((m["joined_at"] for m in members if m.get("joined_at")), default=None)
joins = collect_join_greetings(active_members=members, min_joined_at=min_joined)
join_aliases = parse_join_name_aliases(joins, active_mns=master)

annotate_attendees(posts, master, join_aliases)
match_outings_with_reviews(posts)
save_excel(posts, photos, start_ym, end_ym, members=members)
# → 다감노_202509-202603_분석.xlsx 저장
```

## 집계 기준

- **기간** — `(start_ym, end_ym)` YYYYMM 정수 쌍으로 지정하며 양끝을 포함합니다. 출사 공지(`cat=A`)는 **출사일** 기준, 후기·가입인사·사진은 **작성일** 기준. 월별 집계는 연도를 포함한 `YYYYMM` 축을 쓰므로 다년 범위에서도 2025-03과 2026-03이 섞이지 않습니다.
- **활성 vs 비활성** — 작성자/업로더 랭킹(공지·후기·사진·테마사진)은 활성 멤버(`/api/group`의 `ban=N`)만 집계. `ban=Y`는 **강퇴**된 멤버이며 `강퇴멤버` 탭에 쌓입니다(자발적으로 나간 사람은 멤버 목록에 아예 없어 잡히지 않습니다). 후기 본문에서 추출되는 참석자 추적은 **공지 작성자가 탈퇴했어도 유지**.
- **카테고리** (제목 `[태그]`) — 출사: 인물(1:1인물·1:1인물출사 포함)·인물&풍경(구 인풍)·풍경·GN / 활동: 보정·문화. `일반공지`는 태그로 오지 않고 **보정 시트에서 사람이 지정**하는 값입니다(전체 공지 등). 출사가 아니므로 집계에서 빠집니다.
- **취소(펑)** — 제목에 `(펑)`·`[펑]` 포함 시 취소로 집계. 출사별 참석자 표·🎯 출사별 참석자 시트에서는 제외.
- **참석자** — 후기 본문에서 한글 2~4자·영문 2~10자 토큰을 추출 → 활성 멤버 닉네임(`mn`) 매칭 → 가입인사 자동 매핑 → 사용자 매핑(또는 🚪 탈퇴 / `이름 ❌` 노이즈) 순으로 해소. 매칭된 출사 공지의 참석자로 부착됩니다.
- **출사 ↔ 후기 매칭** — 후기 제목/본문에서 추정한 출사일(없으면 작성일)로 거리 ≤ ±7일(추정 성공) / ±45일(fallback) 내 공지 후보를 찾고, 카테고리 일치 시 -100, 작성자 일치 시 -5 가산점. 거리 가까운 후기부터 공지를 선점해 1:1 매칭. 제목 단어는 매칭에 사용하지 않습니다.
- **테마사진** — 댓글이 달린 사진(`rn>0`)을 테마 참여로 **추정**합니다. 댓글 내용은 비공개라 개수만 활용합니다. 추정이 틀린 사진은 📷 사진 탭의 🎨 테마사진에서 **테마 아님**에 체크해 뺄 수 있고(`테마사진보정` 시트에 남습니다), 제출 인원·참여자·테마사진 수가 함께 갱신됩니다.
- **본문 잘림** — 소모임 목록 API는 본문을 일정 길이에서 끊어 보냅니다. 그 길이는 문서에 없으므로 **상수로 박지 않고 데이터에서 알아냅니다** — 서로 다른 글 3건 이상이 정확히 같은 길이에서 끝나고 그보다 긴 글이 하나도 없으면 그 길이가 벽입니다. 기간을 자르기 전 **전체 게시글**로 재고, 40자 미만의 벽은 판단하지 않습니다 — 짧은 글 몇 개가 우연히 같은 길이인 쪽이 훨씬 흔하고, 거짓 경고는 진짜 경고를 죽입니다. 벽에 닿은 후기는 👥 참석 & 후기 탭의 📖 후기에서 **월 이름 옆 ✂️와 잘림 건수**, 그리고 카드 맨 위 **빨간 배지**로 표시됩니다(`✂️ 잘린 후기만 보기` 스위치로 걸러 볼 수도 있습니다). 잘린 후기는 이름을 이미 뽑았더라도 **뒤쪽 참석자가 통째로 빠졌을 수 있으므로** `참석자보정` 후보로 올라갑니다.
- **인기** — 좋아요 수로 정렬하고 댓글 수를 함께 표기.
- **동명이인** — 같은 닉네임 활성 멤버가 둘 이상이면 후기 본문에선 분리 불가 → 한 명으로 합쳐 집계됨을 ⚠️로 마킹.
- **월별 신규 가입** — **가입인사(`cat=J`) 작성자 기준**입니다. 이 모임은 가입인사를 쓰지 않으면 12시간 안에 강퇴하므로 가입인사가 곧 제대로 가입한 사람의 명단이고, 인사 글은 사람이 나가도 남아 있어 **이탈까지 셀 수 있습니다.** 잔류 판정은 작성자 `wid` ↔ 현재 멤버 `mid`라 닉네임을 바꿔도 흔들리지 않습니다.
  > 현재 멤버의 `joined_at`으로 세면 **나간 사람이 빠져 이탈이 많았던 달일수록 가입이 적어 보입니다** — 정반대로 읽힙니다. 그 기간에 수집된 가입인사가 없을 때만 그 방식으로 폴백하고, 화면에 경고를 띄웁니다.

## 구글 연동 설정 (필수)

원본과 보정이 모두 구글 드라이브에 살기 때문에 이 설정 없이는 앱이 동작하지 않습니다. **배포자가 한 번만** 하면 되고, 앱 사용자는 구글 계정을 만질 일이 없습니다.

### 왜 서비스 계정인가

사용자 구글 로그인(OAuth)은 Streamlit Community Cloud와 맞지 않습니다. refresh token을 저장할 영구 디스크가 없어 앱이 잠들었다 깨면 매번 다시 로그인해야 하고, 수집 직후 자동 저장 같은 동작이 사용자 세션에 묶입니다. 서비스 계정은 **앱 자체가 신원을 갖기 때문에** 로그인 없이 항상 동작합니다.

### 설정

1. [Google Cloud Console](https://console.cloud.google.com)에서 프로젝트 생성 → **Google Drive API**와 **Google Sheets API** 사용 설정
2. **서비스 계정** 생성 → 키 추가 → **JSON** 다운로드
3. 구글 드라이브에 **비공개 폴더**를 만들고, 서비스 계정 이메일(`...@....iam.gserviceaccount.com`)에 **편집자**로 공유 → 폴더 URL의 `folders/` 뒤 문자열이 `folder_id`
4. **그 폴더 안에 빈 스프레드시트 2개를 직접 만들고** 이름을 정확히 아래로 지정:

   | 파일 이름 | 용도 |
   |---|---|
   | `다감노_raw` | 수집 데이터 |
   | `다감노_보정` | 사람이 채우는 보정 |

   탭은 만들지 않아도 됩니다 — 앱이 알아서 만듭니다.
5. `.streamlit/secrets.toml`(배포 시에는 Streamlit Cloud → 앱 **Settings → Secrets**)에 입력:

```toml
[gsheets]
credentials = '''
{ "type": "service_account", "project_id": "...", "private_key": "-----BEGIN PRIVATE KEY-----\n...", "client_email": "...@....iam.gserviceaccount.com", ... }
'''
folder_id = "1AbC..."

# 선택 — 넣으면 이름으로 찾는 과정을 건너뜁니다 (아래 참고)
# raw_file_id = "1bnh..."
# correction_file_id = "1XyZ..."

[auth]
password = "관리자만 아는 값"
```

앱은 그 폴더에서 두 파일을 **이름으로 찾아** 씁니다. URL을 붙여넣을 필요가 없습니다.

> 💡 **이름 대신 파일 id로 고정할 수 있습니다.** 시트 URL의 `/d/` 와 `/edit` 사이 문자열을 `raw_file_id`·`correction_file_id`에 넣으면 이름 탐색을 아예 건너뜁니다. 이름을 바꾸거나 사본을 만들어도 앱이 헷갈리지 않습니다.
>
> 이름으로 찾을 때 **글자 하나만 달라도 "파일이 없다"가 되고, 앱이 새로 만들려다 403**이 납니다. 앱은 앞뒤 공백과 대소문자, 맥에서 만든 이름의 자소 분리(NFD)까지는 알아서 맞춰 주고, 그래도 못 찾으면 **폴더 안에 실제로 어떤 이름들이 있는지 에러 메시지에 보여 줍니다.**

> ⚠️ **시트를 왜 직접 만들어야 하나** — 구글 드라이브에서는 파일을 만든 주체가 소유자가 되는데, **서비스 계정은 저장 용량이 0이라 파일을 소유할 수 없습니다.** 폴더를 편집자로 공유해도 "만들기"는 안 되고 `storageQuotaExceeded`(403)가 납니다. 사람이 만들면 소유자가 본인이 되고 서비스 계정은 편집만 하므로 문제가 없습니다.
>
> Google Workspace를 쓴다면 **공유 드라이브(Shared Drive)** 안에 폴더를 두는 방법도 있습니다. 그 경우 파일을 드라이브가 소유해서 앱이 직접 만들 수 있습니다. 개인 Gmail 계정에는 공유 드라이브가 없습니다.

> ⚠️ **`credentials`는 반드시 `'''`(작은따옴표 3개)로 감싸세요.** TOML에서 `"""`는 이스케이프를 해석하기 때문에 `private_key`의 `\n`이 실제 줄바꿈으로 바뀌어 JSON 파싱이 깨집니다.

> ⚠️ **자격증명을 `.py` 파일에 넣지 마세요.** 이 앱은 GitHub 저장소에서 배포되므로 코드에 넣은 키는 그대로 커밋됩니다. `.streamlit/secrets.toml`은 `.gitignore`에 있고, 배포 시 Secrets 패널 내용은 저장소에 들어가지 않습니다.

### 보안

- **보정 시트에는 실명이 들어갑니다.** 폴더를 링크 공유로 열어 두지 마세요 — 본인과 서비스 계정에만 공유해야 합니다.
- **`이름매핑1`을 채우면 분석 결과 파일에도 실명이 들어갑니다** (`원석사진(정원석)` 형태). 엑셀을 내려받아 공유하실 때 유의하세요.
- **비밀번호 게이트는 실질적인 보안이 아닙니다.** 평문 비교이고 해싱·시도 제한·세션 만료가 없습니다. 공개된 앱 주소로 우연히 들어오는 것을 막는 수준이며, 데이터를 실제로 지키는 것은 위의 폴더 공유 설정입니다. `[auth]`를 넣지 않으면 게이트를 건너뜁니다(로컬 개발용).
- **스코프를 좁히려면** `core/gsheets.py`의 `SCOPES`를 `.../auth/drive.file`로 바꾸면 앱이 만든 파일에만 접근합니다. 대신 사람이 손으로 만들거나 복사한 시트는 앱이 볼 수 없게 됩니다.
- 키가 유출되면 GCP 콘솔에서 폐기 후 재발급하고 Secrets만 갱신하면 됩니다.

## 배포 (Streamlit Community Cloud · 무료)

서버 비용 0원이며 `main`에 push하면 자동 재배포됩니다. **Deploy 클릭은 본인 GitHub/Streamlit 계정**으로 진행해야 합니다(대행 불가).

1. https://share.streamlit.io → **Sign in** (GitHub 로그인·권한 인가)
2. **Create app** → **Deploy a public app from GitHub**
3. 입력
   - Repository: `idjoopal/somoim-analyzer`
   - Branch: `main`
   - Main file path: `streamlit_app.py`
   - App URL: 원하는 서브도메인
4. (선택) Advanced settings → Python 3.11 이상
5. **Deploy** → 1~3분 빌드 후 `https://<서브도메인>.streamlit.app` 발급 → 공유

운영 중에는 앱 우측 하단 **Manage app**에서 빌드·런타임 로그를 볼 수 있습니다. 일정 시간 미접속 시 sleep 되고, 다음 접속 때 수십 초 내 자동 기동됩니다.

## 주의사항

- **비공식 API 기반** — 소모임 응답 구조나 인증 정책이 바뀌면 수집이 멈출 수 있어 정기적인 동작 확인이 필요합니다. 댓글 **내용**은 인증 한계로 가져오지 않습니다(개수만 활용).
- **타임스탬프 보정값**(`+1_000_000_000`)은 실측 추정값이라, 큰 오차가 보이면 재추정이 필요합니다.
- **사진 CDN URL**은 현재 무기한이지만 만료될 수 있으니 필요한 사진은 즉시 보관을 권장합니다.
- **`/api/articles` 페이지 한도** — 200페이지 한도가 있지만 `cat=J` 서버 필터로 가입인사만 받고 활성 멤버 전원 확보 시 조기 종료하므로 실제로 한도에 닿을 일은 거의 없습니다.
- 분석 대상은 **다감노 모임 한 곳**(`GROUP_ID` 하드코딩)입니다. 기간이 길면 `/api/articles` 200페이지 한도에 걸릴 수 있는데, 그때는 앱이 경고를 띄우므로 기간을 나눠 수집하세요.
- **삭제된 글은 raw에 남습니다** — 수집은 id 기준 upsert라 소모임에서 지워진 글을 감지하지 못합니다. 필요하면 보정 시트의 `제외` 열로 분석에서 빼세요.
- **이용약관** — 자동 수집이 소모임 약관과 충돌할 수 있으므로 개인 분석 용도로만 사용하세요.
