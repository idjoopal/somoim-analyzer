## 1. 이 앱은 무엇인가요?

**다감노 분석**은 소모임 앱에 올라온 다감노의 게시글·사진·멤버 정보를
자동으로 모아서, 아래 질문에 답을 주는 웹 페이지입니다.

- 이번 시즌에 출사가 몇 번 있었고, 누가 열었나?
- 각 출사에 누가 참석했나? 누구와 누가 자주 같이 다니나?
- 테마사진은 누가 꾸준히 내고 있나?
- 새로 가입한 멤버는 잘 정착하고 있나? 나간 사람은 누구인가?

설치할 것은 없습니다. **인터넷 주소로 접속해서 비밀번호만 입력하면** 됩니다.
휴대폰보다는 화면이 넓은 컴퓨터에서 보시는 것을 추천합니다.

### 꼭 알아야 할 개념 하나 — "보정"

소모임 글은 사람이 자유롭게 쓰기 때문에, 컴퓨터가 자동으로 알아내지 못하는
것이 생깁니다. 예를 들어:

- 후기 본문에 "캐논, 나무, 바다 참석!"이라고 적혀 있어도, "캐논"이 멤버
  목록의 어느 닉네임인지 컴퓨터는 모릅니다.
- 공지 제목에 출사 날짜가 안 적혀 있으면 언제 출사인지 모릅니다.
- 소모임에서 글을 보내줄 때 **긴 본문은 중간에 잘라서** 보내기 때문에,
  뒤쪽에 적힌 참석자 이름이 통째로 빠지기도 합니다.

이런 빈틈을 사람이 채워 주는 일이 **보정**입니다. 보정은 구글 스프레드시트에
한 번만 적으면 되고, **한 번 적은 내용은 데이터를 다시 수집해도 절대
지워지지 않습니다.** 이 앱의 가장 중요한 약속입니다.

## 2. 전체 흐름 한 장 요약

사용은 아래 순환을 도는 것이 전부입니다.

```
 📥 1단계 — 데이터 수집
     사이드바에서 기간을 고르고 [수집 시작]
     (시즌에 한 번, 또는 새 글이 쌓였을 때)
          ↓
 ✍️ 2단계 — 구글 시트에서 보정
     [📕 보정 시트 열기] → 빈칸 채우기
     (수집 직후 한 번 몰아서, 이후엔 생길 때마다 조금씩)
          ↓
 🔄 앱으로 돌아와 [새로고침]
          ↓
 📊 3단계 — 7개 탭에서 결과 확인
     개요 맨 위 "🎯 신뢰도"부터 읽기
          ↓
 🔍 4단계 — 인사이트를 보며 추가 보정
     이상한 숫자 발견 → 화면에서 바로 고치거나
     보정 시트로 가서 고치고 → 다시 [새로고침]
          ↓
 ↺ 새 글이 쌓이면 1단계부터 다시
```

한 번 자리를 잡으면, 평소에는 **3단계(구경)** 만 하다가 새 글이 쌓이면
1→2를 한 번씩 돌리는 식이 됩니다.

## 3. 시작하기

1. 전달받은 **웹 주소**로 접속합니다.
2. **비밀번호**를 입력합니다. (관리자에게 전달받은 값)
3. 처음 화면이 열리면:
   - 이미 수집해 둔 데이터가 있으면 → 곧바로 분석 결과가 보입니다.
   - 아직 아무것도 없으면 → "사이드바 📥 수집에서 기간을 지정해 데이터를
     받아오세요"라는 안내가 보입니다.

화면 왼쪽의 **사이드바**가 조종석입니다. 접혀 있으면 왼쪽 위의 `>` 표시를
눌러 펼치세요. 사이드바에는 이런 것들이 있습니다.

| 사이드바 항목 | 하는 일 |
|---|---|
| **📥 수집** | 기간을 골라 소모임에서 데이터를 받아옵니다 |
| **🗂 데이터 현황** | 지금까지 쌓인 글·사진·멤버 수 |
| **📗 raw 시트 열기** | 원본 데이터 구글 시트를 엽니다 (구경용 — 고치지 마세요) |
| **📕 보정 시트 열기** | **여러분이 채우는** 구글 시트를 엽니다 |
| **🔄 새로고침** | 시트에서 고친 내용을 화면에 반영합니다 |

## 4. 1단계 — 데이터 수집

사이드바 **📥 수집**에서:

1. **시작 년/월 ~ 종료 년/월**을 고릅니다.
   - 한 해 전체: `2026년 1월 ~ 2026년 12월`
   - 한 달만: 시작과 종료를 같은 달로
   - **해를 넘기는 활동 시즌도 그대로 됩니다**: `2025년 9월 ~ 2026년 3월`
2. **[수집 시작]** 버튼을 누릅니다.
3. 진행 표시가 끝날 때까지 기다립니다. (기간이 길수록 오래 걸립니다)

알아두면 좋은 것:

- **겹쳐서 수집해도 안전합니다.** 이미 받아 둔 글은 최신 내용으로 갱신될
  뿐, 중복으로 쌓이지 않습니다.
- **보정한 내용은 건드리지 않습니다.** 몇 번을 다시 수집해도, 여러분이
  시트에 적은 값은 그대로 남습니다.
- 기간을 24개월보다 길게 잡으면 "나눠서 수집하세요"라는 주의가 뜹니다.
  소모임이 한 번에 보내 주는 양에 한계가 있어서인데, 그럴 땐 두세 번에
  나눠 수집하면 됩니다.

수집이 끝나면 앱이 **보정이 필요한 항목을 보정 시트에 자동으로 채워
넣습니다.** 여러분은 시트를 열어 빈칸만 채우면 됩니다. → 다음 장으로.

## 5. 2단계 — 구글 시트에서 보정하기

**이 장이 이 설명서의 핵심입니다.** 천천히 읽어 주세요.

### 5-1. 구글 시트가 두 개입니다 — 역할이 다릅니다

| 문서 | 누가 쓰나 | 여러분이 할 일 |
|---|---|---|
| 📗 **다감노_raw** | **앱이** 씁니다. 수집한 원본 데이터가 그대로 담깁니다. | **아무것도 고치지 마세요.** 정렬하거나 내려받아 구경하는 것은 괜찮습니다. |
| 📕 **다감노_보정** | **여러분이** 씁니다. 앱은 읽기만 하고, 빠진 항목을 추가만 합니다. | 빈칸을 채웁니다. 이 문서 전체가 여러분의 작업 공간입니다. |

이렇게 나눈 이유: 원본과 사람 판단이 한곳에 섞이면, 다시 수집할 때 사람이
적은 것까지 덮어써 버릴 수 있습니다. 둘을 물리적으로 분리해 두면 **앱은
raw만 덮어쓰고, 보정은 영원히 안전**합니다.

### 5-2. 모든 탭에 공통인 규칙

보정 시트의 어느 탭에서든 똑같이 적용됩니다.

- **빈칸 = "아직 보정 안 함"** 입니다. 비워 두면 앱이 자동 판단을 그대로
  씁니다. 틀린 값을 넣는 것보다 비워 두는 편이 낫습니다.
- **행을 지우지 마세요.** 지워도 다음에 앱이 다시 추가합니다.
- **첫 번째 열(id)을 고치지 마세요.** 그 값이 "이 보정이 어느 글에 대한
  것인지"를 붙잡는 열쇠입니다. 고치면 보정이 엉뚱한 글에 붙거나 사라집니다.
- **회색 참고 열**(제목·빈도 등)은 알아보기 쉬우라고 앱이 채워 준
  값입니다. 고쳐도 반영되지 않습니다.
- **열 이름 칸에 마우스를 올리면** 그 칸에 무엇을 넣는지 설명이 뜹니다.
- 일부 칸은 **드롭다운**(▼)이라 목록에서 고르기만 하면 됩니다.
- 시트 맨 앞의 **`_사용법` 탭**에 전체 규칙이 다시 정리되어 있습니다.

⚠️ **이 시트에는 멤버들의 실명이 들어갑니다.** 링크 공유를 켜거나 외부에
전달하지 마세요.

### 5-3. 탭 ① `이름매핑1` — 멤버 실명 (여기부터 시작!)

**무엇:** 멤버마다 실명을 적는 명단입니다.
**왜 먼저:** 후기 본문에는 닉네임보다 실명("김캐논", "이소니")이 더 자주
나옵니다. 실명을 채워 두면 앱이 "캐논 → 캐논사진 님"을 스스로 알아내서,
**다음 탭(②)에서 손볼 일이 크게 줄어듭니다.**

| 열 | 설명 |
|---|---|
| `멤버 id` | 🔒 앱이 채움 — 고치지 마세요 |
| `닉네임` | 회색 참고 — 지금 소모임 닉네임 |
| `실명` | ✍️ **여기를 채우세요** (예: 김캐논) |
| `비고` | 자유 메모 (앱은 읽지 않음) |

작성 예시:

| 멤버 id | 닉네임 | 실명 | 비고 |
|---|---|---|---|
| (자동) | 캐논사진 | 김캐논 | |
| (자동) | 나무 | 이소니 | |

- 전 멤버가 **닉네임 가나다순**으로 미리 깔려 있어서, 갖고 계신 명단을
  실명 열에 통째로 붙여넣기 좋습니다.
- 가입인사에서 자동으로 찾아낸 실명은 **미리 채워져** 있습니다.
- 이 명단의 열쇠는 닉네임이 아니라 멤버 id입니다. 그래서 **누가 닉네임을
  바꿔도 실명이 자동으로 따라갑니다.**
- 실명을 채우면 분석 화면 어디서나 `캐논사진(김캐논)`처럼 함께 표시됩니다.
  닉네임과 실명이 같으면 하나만 표시됩니다.

### 5-4. 탭 ② `후기이름매핑` — 그래도 남은 이름 처리

**무엇:** 후기 본문에서 뽑았지만, ①의 실명으로도 멤버와 이어지지 않은
이름들입니다. 대개 **오타, 이미 나간 멤버, 이름이 아닌 단어** 셋 중
하나입니다.

| 열 | 설명 |
|---|---|
| `이름토큰` | 🔒 본문에서 발견된 표기 그대로 — 고치지 마세요 |
| `처리` | ✍️ **여기를 채우세요** (드롭다운) |
| `빈도` | 회색 참고 — 몇 번 나왔나 (많이 나온 것부터 처리하세요) |
| `비고` | 자유 메모 |

`처리` 칸에 넣는 값 세 가지:

| 상황 | 넣는 값 |
|---|---|
| 오타·별칭이고, 누군지 안다 | 드롭다운에서 **그 멤버의 닉네임** 선택 |
| 지금은 나간(탈퇴·강퇴) 사람 | `__LEFT__` — 한글로 `탈퇴`나 `강퇴`라고 적어도 됩니다 |
| 애초에 사람 이름이 아니다 (지명·장비명 등) | `__NOISE__` — 한글로 `노이즈`, 또는 `❌`도 됩니다 |

작성 예시:

| 이름토큰 | 처리 | 빈도 | 비고 |
|---|---|---|---|
| 캐논이 | 캐논사진 | 12 | |
| 박후지 | 탈퇴 | 3 | 작년에 나감 |
| 탐론 | ❌ | 2 | 렌즈 얘기 |

### 5-5. 탭 ③ `공지보정` — 출사 공지의 날짜·분류

**무엇:** 앱이 출사 날짜나 카테고리를 자동으로 확정하지 못한 공지들입니다.
소모임에서 해당 공지 원문을 열어 보고 채웁니다.

| 열 | 설명 |
|---|---|
| `공지 id` | 🔒 고치지 마세요 |
| `제목` | 회색 참고 |
| `카테고리` | ✍️ 드롭다운: `인물` `인물&풍경` `풍경` `GN` `보정` `문화` `일반공지` |
| `출사일` | ✍️ 실제 출사한 날짜를 `2026-03-14` 형식으로. **공지를 올린 날이 아닙니다** |
| `취소` | ✍️ 출사가 취소(펑)됐으면 `TRUE` |
| `제외` | ✍️ 출사 공지가 아니거나 집계에서 빼야 하면 `TRUE` |
| `비고` | 자유 메모 |

- **채운 칸만 반영됩니다.** 카테고리만 고치고 싶으면 카테고리만 채우세요.
- 정기 모임 안내처럼 **어느 카테고리도 아닌 전체 공지**는 `일반공지`를
  고르세요. 출사 통계에서 깔끔하게 빠집니다.

### 5-6. 탭 ④ `참석자보정` — 후기의 참석자 명단

**무엇:** 두 종류의 후기가 올라옵니다.

1. 본문에서 **참석자를 한 명도 못 뽑았거나**, 뽑았는데 이상한 후기
2. **본문이 잘린** 후기 — 이름을 몇 명 뽑긴 했지만, 잘린 뒷부분에 더
   있었을 수 있어 그 명단이 전부라고 믿을 수 없는 경우

| 열 | 설명 |
|---|---|
| `후기 id` | 🔒 고치지 마세요 |
| `제목` | 회색 참고 |
| `참석자` | ✍️ **여기를 채우세요** — 쉼표로 구분한 닉네임 |
| `비고` | 자유 메모 |
| `추출된 참석자` | 회색 참고 — 앱이 본문에서 뽑아낸 명단 |
| `본문길이` | 회색 참고 — 본문 글자 수 |
| `본문상태` | 회색 참고 — `⚠️ 잘림 의심` 또는 `온전` |

채우는 요령:

- 소모임에서 그 후기 **원문을 열어** 실제 참석자를 확인하고, `참석자` 칸에
  `캐논사진, 나무, 바다`처럼 쉼표로 적습니다.
- **여기 적은 명단이 통째로 채택됩니다**(앱이 뽑은 것에 더해지는 게
  아닙니다). 그러니 **글쓴이 본인도 참석했다면 함께 적으세요.**
- `본문상태`가 `⚠️ 잘림 의심`이면 → 본문 뒷부분이 안 온 후기입니다.
  원문과 대조가 꼭 필요합니다.
- `본문상태`가 `온전`이면 → 본문은 다 왔는데 이름 표기가 특이해서 못 뽑은
  경우입니다. `추출된 참석자`를 참고해 채우세요.
- 원문을 확인했는데 **앱이 뽑은 명단이 이미 맞다면**, `추출된 참석자`
  내용을 그대로 `참석자` 칸에 복사해 넣으세요. **빈칸으로 두면 앱은 끝까지
  "아직 확인 안 함"으로 세기 때문에**, 복사해 넣어야 남은 건수가 줄어듭니다.

작성 예시:

| 후기 id | 제목 | 참석자 | 비고 | 추출된 참석자 | 본문길이 | 본문상태 |
|---|---|---|---|---|---|---|
| (자동) | 3/14 풍경출사 후기 | 캐논사진, 나무, 바다, 하늘 | 원문 확인함 | 캐논사진, 나무 | 120 | ⚠️ 잘림 의심 |

### 5-7. 탭 ⑤ `테마사진보정` — 손대지 않아도 되는 탭

**무엇:** "댓글이 달린 사진"을 앱이 테마사진 참여로 추정하는데, 그 추정이
틀렸을 때 바로잡은 기록입니다.

**이 탭은 시트에서 직접 채우지 않습니다.** 앱의 📷 사진 탭에서 사진을
눈으로 보며 **[테마 아님]에 체크하고 [변경 저장]** 을 누르면 여기에 자동으로
기록됩니다(→ [7장](#7-4단계--인사이트를-보며-추가-보정)). 시트에는 그
결과가 남을 뿐입니다.

### 5-8. 보정을 마쳤으면 — 🔄 새로고침

앱으로 돌아와 사이드바의 **[🔄 새로고침]** 을 누르세요. 시트에서 고친
내용이 분석에 반영되고, 화면 곳곳의 숫자가 갱신됩니다.

## 6. 3단계 — 결과 화면 7개 탭 읽는 법

### 읽기 전에 — 🎯 신뢰도 패널부터

**📊 개요 탭 맨 위**에 "이 숫자를 얼마나 믿어도 되는가"를 알려 주는 표가
있습니다. 결과를 읽기 전에 여기부터 보세요.

| 항목 | 뜻 |
|---|---|
| 실명 미기입 멤버 | `이름매핑1`에서 실명이 빈 멤버 수 |
| 참석자 못 뽑은 후기 | `참석자보정`에서 아직 안 채운 후기 수 |
| 해소 안 된 이름 | `후기이름매핑`에서 아직 처리 안 한 이름 수 |
| 검토 대상 공지 | `공지보정`에서 아직 안 채운 공지 수 |
| 공지와 안 이어진 후기 | 짝이 될 출사 공지를 못 찾은 후기 (참석 집계에서 빠짐) |

건수가 많이 남아 있으면 참석 관련 숫자는 실제보다 **작게** 나옵니다.
"참석이 적네?"라고 읽기 전에 보정이 얼마나 남았는지 먼저 확인하세요.

### 📊 개요

전체 요약 — 진행/취소 비율, 월별 활동 추이, 좋아요·댓글 합계, 최고 인기
게시글, 활동 종합 랭킹.

### 📌 출사

월별 진행/취소, 출사 공지 작성 순위(취소율 포함), 출사당 평균 참석 인원,
공지 전체 목록. 아래쪽 **🏷️ 카테고리** 구역에서 인물/풍경 등 카테고리별
추이·작성자·좋아요 통계를 봅니다.

### 👥 참석 & 후기

- 멤버별 참석 횟수와 월별 참석표, 출사별 참석자 명단.
- 멤버별 참석 횟수의 `선호 카테고리`는 많이 간 순으로 **최대 5개**까지
  보여 줍니다(카테고리가 모두 7종이라 사실상 전체 분포입니다).
- **함께 간 사람** 표 읽는 법: 두 사람이 같은 출사에 함께 간 횟수 상위
  **40쌍**입니다. `A 참석`은 그 사람의 전체 참석 횟수, `A 기준`은 그중 상대와
  함께한 비율(막대). **같은 "함께 8회"라도** 12회 참석한 사람에겐 대부분
  (67%)이고, 20회 참석한 사람에겐 일부(40%)일 수 있어 양쪽을 다 보여줍니다.
  여기는 **전체 상위 40쌍**이라 참석이 적은 사람은 올라오지 않습니다 —
  특정인의 동행 전체는 🔎 멤버 상세 탭에서 봅니다.
- **📖 후기 본문 상세 확인**: 후기 원문과 뽑아낸 참석자를 월별로 봅니다.
  본문이 잘린 후기는 **월 이름 옆 ✂️ 표시**와 **카드 위 빨간 배지**로
  표시됩니다. `✂️ 잘린 후기만 보기` 스위치로 그것만 걸러 볼 수 있습니다.

### 📷 사진

업로드 순위, 월별 업로드, 인기 사진 갤러리(좋아요 상위 12장). 아래쪽
**🎨 테마사진** 구역이 테마사진 확인·보정 작업대입니다(다음 장).

### 🖼 갤러리

**올라온 사진을 전부 볼 수 있는 곳**입니다. 📷 사진 탭의 인기 갤러리는
좋아요 상위 12장뿐이지만, 여기서는 수천 장이라도 끝까지 넘겨 볼 수 있습니다.

맨 위에 **보기**를 고르는 스위치가 있습니다. 이게 이 탭의 핵심입니다.

| 보기 | 이럴 때 |
|---|---|
| **월별** | "작년 3월에 뭘 찍었더라" — 달 이름을 눌러 펼칩니다 |
| **전체** | "전 기간 좋아요 1등부터" — 달 구분 없이 한 줄로 늘어놓습니다 |

**월별에서는 정렬이 그 달 안에서만 걸립니다.** 전 기간에서 좋아요·댓글이
가장 많은 사진을 찾으려면 반드시 **전체**로 바꾸세요.

- **업로더**를 고르면 그 사람이 올린 사진만 봅니다(각자 몇 장인지도 함께
  나옵니다). **테마사진만** 스위치로 댓글 달린 사진만 볼 수도 있습니다.
- **정렬**은 최신순 · 오래된순 · 좋아요순 · 댓글순.
- 사진은 **한 번에 40장씩** 나오고, 아래위 **페이지** 칸으로 넘깁니다.
  **닫아 둔 달은 아예 불러오지 않습니다** — 그래서 사진이 아무리 많아도
  화면이 무거워지지 않습니다.
- 이 탭도 위쪽 **분석 기간**을 따릅니다. 기본값이 수집한 전 기간이라
  평소에는 올라온 사진 전부와 같습니다.

### 🧑‍🤝‍🧑 멤버

- 활성 멤버·운영진·기기 비율·유령 멤버(활동 0건)·동명이인 주의 표시.
- **월별 신규 가입**: 가입인사를 쓴 사람 기준으로 **가입 / 잔류 / 이탈**을
  나눠 보여줍니다. (다감노는 가입인사를 안 쓰면 12시간 안에 내보내는
  규칙이라, 가입인사 = 실제 가입자 명단입니다.) 나간 멤버 목록에는 마지막
  활동일과 활동 기간도 함께 나옵니다.
- 최근 조용해진 멤버, 신규 멤버 정착(가입 후 첫 참석까지 걸린 날).

### 🔎 멤버 상세

**한 사람만 골라서 그 사람 이야기만 보는 탭**입니다. 다른 탭은 전부 "한 줄이
한 사람"인 표라, 누구 한 명을 알아보려면 탭 다섯 개를 오가며 표에서 그 이름을
눈으로 찾아야 했습니다.

맨 위 드롭다운에서 멤버를 고르면 아래가 통째로 그 사람 것으로 바뀝니다.
목록에는 참석·글·사진 수가 함께 적혀 있어, 활동이 없는 사람을 골라 놓고
"화면이 비었네?" 하는 일이 없습니다.

- **배지** — 운영진 / 유령(활동 0건) / 휴면(3개월 넘게 참석 없음) /
  ⚠️ 동명이인.
- **🏆 칭호** — 그 사람의 활동에서 뽑은 별명을 최대 3개까지. `테마사진의
  제왕`·`○○님 출사가세요?`·`아이고 어르신`·`이게 본업이에요` 같은 것들이고,
  밑에 **왜 붙었는지 근거**가 함께 나옵니다 — 그 사람의 숫자만이 아니라
  "1등이라서"인지 "상위 15%라서"인지까지 적어 두어, 무엇을 보고 준 칭호인지
  읽고 알 수 있습니다. **재미로 붙이는 것**이니 너무 진지하게
  보지 마세요. 선택한 **분석 기간 안의 활동**으로만 매기므로 기간을 좁히면
  달라집니다(`아이고 어르신`만은 가입일 기준이라 안 바뀝니다).
  > **칭호마다 정원이 있습니다** — 보통 9명, `○○님 출사가세요?`와 카테고리
  > 칭호는 5명까지입니다. 스무 명이 받는 것은 칭호가 아니라 그 모임의 평균이라
  > 그렇습니다. 그래서 **조건을 만족해도 다른 분들이 더 활발하면 안 붙을 수
  > 있습니다.** 활동이 비슷하면 칭호마다 순서를 다르게 섞어 골고루 돌아갑니다.

  어떤 칭호가 있고 각각 언제 붙는지는 [9장 부록](#9-부록---칭호-전체-목록)에
  전부 적어 두었습니다.
- **숫자 열 개** — 참석·개최한 출사·후기·사진·테마사진, 그리고 참석률·첫
  등장·최근 참석·가입일·마지막 방문.
  > **참석률의 분모는 "후기가 매칭된 출사"뿐입니다.** 후기가 없는 출사는
  > 누가 갔는지 알 방법이 없어서, 그것까지 분모에 넣으면 아무 잘못 없이
  > 모두의 참석률이 낮아집니다.
- **🏅 모임 내 순위** — 참석 / 개최 / 사진이 각각 몇 등인지. "12회 참석"
  만으로는 그게 많은 건지 알 수 없기 때문입니다.
  > **같은 횟수면 같은 등수**입니다(1·2·2·4등). 괄호 안 숫자는 그 활동을
  > 한 번이라도 한 사람 수이고, 개최는 **펑이 아닌 출사를 연 사람**만
  > 셉니다 — 펑만 낸 사람은 개최 순위가 안 붙습니다.
- **월별 활동 추이** — 참석·개최·후기·사진을 한 차트에. 언제 활발했고
  언제 조용해졌는지 한눈에 보입니다.
- **선호 카테고리** — 참석한 출사의 카테고리 전체 분포(도넛).
- **개최한 출사** — 취소(펑)까지 포함한 목록과 취소율.
- **작성한 후기** — 바로 위 "개최한 출사" 밑에 붙여 두었습니다. **후기를 잘
  쓰고 있는지 바로 보이게** 하려는 것입니다. 맨 위에 `본인이 연 출사 12건
  중 9건은 본인이 후기를 썼습니다 (75%)` 한 줄이 나옵니다.
  > 분모에서 **펑은 뺍니다** — 취소된 출사는 후기를 쓸 일이 없으니까요.
  > 그리고 **후기를 꼭 개최자가 쓰는 것은 아닙니다.** 나머지는 다른 사람이
  > 썼거나 아직 후기가 없는 경우입니다.
- **참석한 출사** — 언제 어떤 출사에 갔는지 전부.
- **함께 간 사람** — 이 사람과 함께 간 **전원**입니다. 👥 참석 & 후기 탭의
  표는 전체 상위 40쌍만 보여 주므로, 여기 있는 사람이 거기엔 없을 수
  있습니다.
- **사진** — 좋아요 합·장당 좋아요·테마사진 수·테마 참여 월수와 인기 8장.
- **🏆 칭호 분포** (맨 아래, 접혀 있음) — 전 멤버에게 칭호가 어떻게 퍼졌는지
  보는 곳입니다. 평소에는 안 열어도 됩니다. **칭호를 아무도 못 받거나 몇
  사람이 싹쓸이하면 재미가 없는데, 그건 실제로 세어 봐야만 압니다.**
  수령 인원이 0명인 칭호나 하나도 못 받은 사람이 너무 많으면 기준을
  손봐야 한다는 신호입니다. 닫아 두면 계산도 하지 않습니다.

## 7. 4단계 — 인사이트를 보며 추가 보정

결과를 구경하다가 "어? 이거 이상한데"를 발견하는 순간이 진짜 보정
타이밍입니다. 고치는 방법이 두 가지로 나뉩니다.

### 화면에서 바로 고치는 것 — 🎨 테마사진

📷 사진 탭 → 🎨 테마사진 구역:

1. 월 이름을 눌러 펼치면 그 달의 테마사진들이 보입니다.
2. 테마사진이 아닌데 잘못 들어온 사진이 있으면, 사진 아래 **[테마 아님]**
   에 체크하세요. 체크해도 화면이 처음부터 다시 뜨지 않으니, 펼쳐 둔 채로
   **여러 장을 이어서** 체크하면 됩니다.
3. 다 골랐으면 위쪽의 **[💾 변경 저장]** 을 누르세요. 이때 시트에 기록되고
   제출 인원·참여자 수가 즉시 갱신됩니다. **저장을 누르기 전까지는 아무
   것도 반영되지 않습니다** — 노란 경고가 "저장하지 않은 변경 n건"을 계속
   알려 줍니다.
4. 잘못 체크했다면: 저장 버튼 바로 아래 **🚫 테마 아님으로 표시한 사진**
   목록을 펼쳐 체크를 풀고 다시 [변경 저장] 하면 됩니다.

### 시트로 돌아가 고치는 것 — 그 외 전부

| 화면에서 본 것 | 가는 곳 |
|---|---|
| ✂️ 표시가 붙은 잘린 후기 | `참석자보정` — 원문 확인 후 참석자 채우기 |
| 참석자가 비어 있는 출사 | `참석자보정` |
| 날짜·분류가 이상한 공지 | `공지보정` |
| 이름이 이상하게 표시되는 멤버 | `이름매핑1` 또는 `후기이름매핑` |

시트에서 고쳤으면 → 사이드바 **[🔄 새로고침]** → 숫자가 갱신됩니다.
이 루프를 돌 때마다 신뢰도 패널의 남은 건수가 줄어드는 것이 보일 겁니다.

## 8. 자주 묻는 질문

**Q. "보정 n건 필요"라는데, 어디를 채워야 하나요?**
📊 개요 탭 맨 위 🎯 신뢰도 표의 `어디서` 열이 보정 시트의 탭 이름입니다.
[📕 보정 시트 열기]로 들어가 그 탭에서 값이 빈 행을 채우면 됩니다.

**Q. 데이터를 다시 수집하면 제가 보정한 게 지워지나요?**
아니요. **절대 지워지지 않습니다.** 앱은 보정 시트를 읽기만 하고, 새로
생긴 항목을 추가만 합니다. 몇 번을 다시 수집해도 안전합니다.

**Q. 참석자가 비어 있는 후기가 많아요. 고장인가요?**
고장이 아니라 **소모임이 본문을 잘라서 보내 주기 때문**입니다. 긴 후기는
뒷부분(대개 참석자 명단)이 안 옵니다. 이 앱에서 자동으로 해결할 방법은
없고, `참석자보정`에서 원문과 대조해 채우는 것이 유일한 방법입니다. 잘린
후기에는 ✂️ 표시가 붙습니다.

**Q. `참석자보정`에서, 앱이 뽑은 명단이 맞으면 그냥 두면 되나요?**
비워 두면 앱은 계속 "아직 확인 안 함"으로 셉니다. `추출된 참석자` 내용을
`참석자` 칸에 **복사해 넣어 주세요.** 그래야 확인 완료로 처리되어 남은
건수가 줄어듭니다.

**Q. 후기가 엉뚱한 출사에 붙어 있어요.**
앱은 후기와 공지를 **제목 → 작성자 → 날짜 → 카테고리** 순으로 견줘 짝을
찾습니다. 장소·컨셉 이름이 겹치는 것이 가장 확실한 증거이고, 대개 출사를
연 사람이 후기도 쓰기 때문입니다. 그래도 어긋난다면 대개 셋 중 하나입니다.

- **후기 제목의 날짜가 실제 출사일과 다르다** — 원문 제목을 고치기 어렵다면
  그대로 두셔도 됩니다. 제목이 닮았으면 날짜가 틀려도 찾아갑니다.
- **공지의 출사일이 비어 있거나 틀렸다** → `공지보정`의 `출사일`을 채우세요.
- **공지가 `취소`로 표시되어 있다** → 펑 난 출사는 후보에서 아예 빠집니다.
  실제로 다녀왔다면 `공지보정`에서 `취소`를 지우세요.

**Q. 멤버가 닉네임을 바꿨어요. 실명을 다시 적어야 하나요?**
아니요. 실명은 닉네임이 아니라 멤버 고유번호에 묶여 있어서 **자동으로
따라갑니다.**

**Q. 테마사진에서 [테마 아님]을 잘못 눌렀어요.**
저장 전이라면: [되돌리기(저장 안 함)] 버튼 하나로 전부 취소됩니다.
저장 후라면: 저장 버튼 아래 **🚫 테마 아님으로 표시한 사진** 목록에서
체크를 풀고 다시 [변경 저장] 하면 됩니다.

**Q. 엑셀 내려받기가 안 보여요.**
화면이 크게 개편되는 동안 엑셀 파일이 화면과 다른 내용을 담게 되어 **잠시
숨겨 두었습니다.** 화면과 다른 파일이 공유되면 어느 쪽이 맞는지 알 수 없게
되기 때문입니다. 필요한 원본은 [📗 raw 시트 열기]에서 언제든 구글 시트로
보고 내려받을 수 있습니다.

**Q. 보정 시트를 다른 사람에게 공유해도 되나요?**
⚠️ 시트에는 멤버들의 **실명**이 들어 있습니다. 링크 공유를 켜지 말고,
꼭 필요한 운영진에게만 구글 계정으로 공유하세요.

## 9. 부록 — 🏆 칭호 전체 목록

🔎 멤버 상세 탭에서 이름 아래 붙는 배지들입니다. **재미로 붙이는 것**이고,
선택한 **분석 기간 안의 활동**으로만 매깁니다(`아이고 어르신`만 가입일
기준이라 기간을 바꿔도 안 변합니다).

### 읽기 전에 — 세 가지 규칙

1. **한 사람에게 최대 3개.** 조건을 다섯 개 만족해도 센 것 세 개만 보입니다.
2. **지표가 같으면 한 사람에게 하나만.** 아래 표의 굵은 줄이 지표 묶음입니다.
   `이게 본업이에요`와 `프로 참석러`는 둘 다 참석을 재는 칭호라 같이 붙지
   않습니다. 양 끝을 재는 짝(`정출킬러`↔`소수정예`)도 마찬가지입니다.
3. **칭호마다 정원이 있습니다** — 보통 **9명**, `○○님 출사가세요?`·`○○와
   환상의 콤비`와 카테고리 칭호는 **5명**. 넘치면 그 칭호가 재는 숫자가 큰
   순으로 자릅니다. 그래서 **조건을 만족해도 안 붙을 수 있습니다.**
   대신 "스무 명이 받는 칭호"는 생기지 않습니다.

> 정원에 밀린 자리는 비워 두지 않고 **그 사람의 다음 칭호로 채웁니다.**
> 활동이 완전히 같은 사람끼리는 칭호마다 순서를 다르게 섞어, 특정인이
> 늘 앞서지 않게 했습니다.

### 동행 — 누구와 다니나

| 칭호 | 붙는 조건 |
|---|---|
| 💞 `○○와 환상의 콤비` | 함께 3회 이상 · **서로에게** 절반이 넘는 사이 |
| 🐾 `○○님 출사가세요?` | 참석 4회 이상 · 내 출사의 60% 이상을 그분과 함께 · 그분의 **전체 출석률보다 15%p 이상** 높을 것 |
| 🕸 다 아는 사람들 이구먼 | 함께 출사해 본 사람 수 상위 20% (4명 이상) |
| 🕊 저 신입 아닌데요 | 참석 3회 이상인데 동행자 수는 하위 25% |

> `○○님 출사가세요?`에서 **그분의 전체 출석률을 빼는 것**이 핵심입니다.
> 거의 모든 출사에 나오는 분이 있으면 누구든 그분과 자주 겹치는데, 그건
> 따라다니는 게 아니라 그냥 확률입니다.

### 참석 · 개최 · 사진 — 얼마나 하나

각 줄은 **1등이면 위 칭호, 아니면 상위 몇 %에 아래 칭호**입니다.

| 지표 | 1등 | 상위 | 최소 조건 |
|---|---|---|---|
| 테마사진 | 🎨 테마사진의 제왕 | 🖌 테마사진 프로 참석러 (상위 15%) | 2장 이상 |
| 개최 | 📢 출사장도 장이다 | 🗣 심심한데 출사쳐야지 (상위 30%) | 펑 아닌 출사 2건 이상 |
| 참석 | 🥾 이게 본업이에요 | 🔥 프로 참석러 (상위 15%) | 3회 이상 |
| 사진 | 📸 여기 제 인스타인데.. | 🖼 부지런한 업로더 (상위 30%) | 5장 이상 |
| 장당 좋아요 | ❤️ 사진 좋아요 1위 | 💗 느좋 사진러 (상위 30%) | 10장 이상 |

> **1등은 모수가 4명 이상일 때만** 인정합니다. 두 사람뿐인 판의 1등은
> 1등이 아니니까요. 장당 좋아요에 "10장 이상"이 붙는 이유도 같습니다 —
> 한 장 올려 좋아요를 많이 받은 것과 꾸준히 잘 찍는 것은 다릅니다.

### 후기 · 속도 — 언제 쓰나

| 칭호 | 붙는 조건 |
|---|---|
| ✍️ 책임감 100만점 | 본인이 연 출사 **5건 이상**에 전부 직접 후기를 씀 (100%) |
| 🙈 아맞다후기 | 출사는 3건 이상 여는데 본인이 쓴 후기가 **0건** |
| 🚀 후기는 따끈할때 | 후기 3건 이상 · 출사일로부터 **평균 1일 안에** 올림 |
| ⚡ 내일 출사가실분? | 개최 3건 이상 · 그중 절반 이상이 **공지 후 이틀 안에 출발** |

> `책임감 100만점`과 `아맞다후기`는 같은 자(자기 출사 후기율)의 양 끝이라
> 한 사람에게 같이 붙지 않습니다.

### 규모 · 균형 · 종합 — 어떻게 다니나

| 칭호 | 붙는 조건 |
|---|---|
| 🎪 정출킬러 | 참석 4회 이상 · **참석한 출사의 평균 인원**이 상위 15% |
| 🤏 소수정예 | 참석 4회 이상 · 참석한 출사의 평균 인원이 하위 15% |
| 👀 소모임에요? 글쎄.. | 참석은 상위 30%인데 올린 사진은 **2장 이하** |
| 🖨 제가 사진이 좀 많아요 | 사진은 상위 30%인데 참석은 **2회 이하** |
| 🎭 골고루 하는 사람 | 참석 5 · 개최 2 · 후기 2 · 사진 5를 **전부** 넘김 |
| 🔥 짧은 기간에 진심 | 참석 5회 이상 · **활동 개월 수로 나눈** 참석 빈도가 상위 30% |

> `정출킬러`↔`소수정예`, `소모임에요? 글쎄..`↔`제가 사진이 좀 많아요`는
> 각각 같은 자의 양 끝입니다.
> `짧은 기간에 진심`은 **늦게 합류한 분을 위한 칭호**입니다. 누적 참석으로는
> 오래 계신 분을 이길 수 없으니, 다닌 개월 수로 나눠 봅니다.

### 습관 · 성향 — 무엇을, 언제

| 칭호 | 붙는 조건 |
|---|---|
| 🛡 펑 한 번 없는 사람 | 출사 **5건 이상**을 열면서 취소가 한 번도 없음 |
| 💥 펑의 달인 | 개최 3건 이상 · 그중 **40% 이상**이 펑 |
| 🌈 잡식성 | 참석 6회 이상 · **4가지 이상** 카테고리 · 가장 많은 것도 40% 이하 |
| 🗓 프로 평일러 | 참석 5회 이상 · 그중 **60% 이상이 평일** |
| 🏞 카테고리 칭호 | 아래 참조 |

카테고리 칭호는 `풍경 사냥꾼` · `인물 전문` · `인풍 애호가` · `GN 마니아` ·
`모여서 보정하실 분?` · `문화?시민`입니다. **세 가지 자 중 하나**만 걸리면
붙습니다:

| 어느 자로 걸렸나 | 뜻 | 근거 문구 |
|---|---|---|
| 내 참석의 **75% 이상**이 그 계열 (참석 6회 이상) | 이 계열만 골라 다닌다 | "참석 12회 중 9회가 인물&풍경" |
| 그 계열 출사의 **40% 이상**에 참석 | 이 계열이 열리면 거의 온다 | "문화 출사 18건 중 8건에 나왔습니다" |
| 그 계열을 모임 평균의 **3배 이상** | 남들보다 유독 이 계열이다 | "전체의 7.6%뿐인 계열인데 내 참석의 31%" |

> 자가 하나뿐이면 **반대쪽 크기의 계열이 통째로 0명**이 됩니다. 첫 번째 자만
> 쓰면 출사가 적은 풍경·보정·문화가 0명이 되고, 두 번째 자만 쓰면 출사가
> 많은 인물&풍경·인물이 0명이 됩니다. 세 번째 자가 그 사이를 메웁니다.
>
> 카테고리와 **요일은 다른 축**이라 `프로 평일러`는 카테고리 칭호와 같이
> 붙을 수 있습니다 — 무엇을 찍느냐와 언제 가느냐는 다른 얘기입니다.

### 연차 — 언제부터 계셨나

| 칭호 | 붙는 조건 |
|---|---|
| 🌳 아이고 어르신 | **가입일이 2025-06-01 이전** · 참석 1회 이상 |
| 🏃 첫 출사 못 참지 | 가입하고 **7일 안에** 첫 출사 |
| 🌱 새싹 | 첫 참석이 최근(분석 기간 끝자락) |
| 🌙 돌아오세요 | **5회 이상** 나오시다 3개월 넘게 조용함 |
| 🚪 아직 첫 출사 전 | 활동 0건이지만 **가입한 지 한 달이 안 됨** |
| 👻 유령 회원 | 이 기간에 글·사진·참석이 **하나도 없음** |

> `아이고 어르신`은 **가입일**로 잽니다. 예전에는 "이 기간에 가장 먼저
> 나타난 사람"이라 분석 기간을 좁히면 대상이 바뀌었는데, 구-감노 시절부터
> 자리를 지켜 왔다는 뜻이 기간에 흔들리면 안 되기 때문입니다.
>
> **가입인사는 활동으로 세지 않습니다.** 가입인사만 쓰고 조용한 분은
> `유령 회원`이 맞습니다. 대신 가입한 지 한 달이 안 된 분에게는
> `아직 첫 출사 전`이 붙습니다 — 아직 나갈 출사가 안 열렸을 수도 있으니까요.

### 0명인 칭호가 보인다면

🔎 멤버 상세 맨 아래 **🏆 칭호 분포**를 펼치면 칭호별 수령 인원이 나옵니다.
0명이 계속 이어지는 칭호가 있다면 두 가지 중 하나입니다.

- **기준이 너무 빡빡하다** — 손봐야 합니다.
- **애초에 그런 데이터가 없다** — 예를 들어 `GN 마니아`는 GN 출사가
  한 건뿐이면 아무도 못 받습니다. 이건 고칠 일이 아닙니다.

어느 쪽인지는 그 칭호가 재는 숫자를 다른 탭에서 확인하면 알 수 있습니다.

이어서 볼 수 있었습니다. 지금은 **모든 데이터가 구글 시트에 자동으로
쌓여서**, 앱을 열면 수집 없이 곧바로 지난 결과가 뜹니다. 파일을 잃어버릴
걱정이 없어졌습니다.

순위표는 1등만 기억에 남습니다. 그래서 각자의 활동에서 뽑은 별명을 최대

예전에는 "댓글 달린 사진 = 테마사진" 추정이 틀려도 고칠 방법이 없었습니다.

## 11. 부록 — 앱이 할 수 없는 것과 그 이유

"이건 왜 안 되지?" 싶은 것들은 대부분 앱의 문제가 아니라, **소모임이
내어 주는 데이터 자체에 없기 때문**입니다. 소모임은 우리에게 데이터를
"목록" 형태로만 보내 주는데, 그 목록에 담기지 않은 정보는 어떤 방법으로도
가져올 수 없습니다. 대표적인 것들을 정리합니다.

### 후기 글에 붙은 사진 보여주기 — ❌ 불가

- **하고 싶은 것:** 후기를 읽으면서 그 글에 올라온 사진도 같이 보기.
- **왜 안 되나:** 소모임이 보내 주는 게시글 정보에는 사진이 "몇 장
  붙어 있는지" **개수만** 있고, 사진 자체(링크)가 없습니다. 반대로 사진
  목록에는 사진은 있는데 **어느 글에 붙었던 사진인지**가 없습니다. 양쪽을
  이어 줄 고리가 어디에도 없습니다.
- **앱은 대신:** 사진은 📷 사진 탭에서 날짜순으로 모아 보여줍니다.

### 잘린 본문의 나머지 받아오기 — ❌ 불가

- **하고 싶은 것:** ✂️ 표시가 붙은 후기의 본문 전체를 자동으로 가져와
  참석자를 끝까지 뽑기.
- **왜 안 되나:** 소모임은 본문을 일정 길이에서 **끊어서** 보내 줍니다.
  전체 본문을 주는 다른 통로를 찾아봤지만 없었고, 심지어 소모임
  웹사이트는 그보다도 짧게 보여줍니다.
- **앱은 대신:** 잘린 후기를 ✂️로 표시하고 `참석자보정`에 올려, 사람이
  소모임 앱에서 원문을 보고 채우도록 안내합니다.
  ([5-6장](#5-6-탭--참석자보정--후기의-참석자-명단) 참고)

### 댓글 내용 읽기 — ❌ 불가

- **하고 싶은 것:** 테마사진의 댓글에 뭐라고 적혔는지 보고 정확히 분류하기.
- **왜 안 되나:** 소모임은 댓글이 **몇 개** 달렸는지만 알려 주고, 내용은
  보내 주지 않습니다.
- **앱은 대신:** "댓글이 달린 사진 = 테마 참여"로 **추정**하고, 틀린 것은
  🎨 테마사진 화면에서 사람이 [테마 아님]으로 바로잡게 했습니다.

### 좋아요 누른 사람 명단 — ❌ 불가

- **하고 싶은 것:** 누가 어떤 글에 좋아요를 눌렀는지 집계하기.
- **왜 안 되나:** 좋아요도 **개수만** 옵니다.
- **앱은 대신:** 좋아요 수 기준의 인기 순위만 보여줍니다.

### 나간 멤버의 명단과 나간 시점 — ⚠️ 우회

- **하고 싶은 것:** 언제 누가 모임을 나갔는지 정확히 알기.
- **왜 안 되나:** 스스로 나간 사람은 멤버 목록에서 **그냥 사라질 뿐**,
  기록이 남지 않습니다. (강퇴된 사람만 별도 표시가 있습니다.)
- **앱은 대신:** **가입인사를 쓴 사람 명단**과 현재 멤버를 대조해 "가입은
  했는데 지금 없는 사람"을 찾아냅니다. 🧑‍🤝‍🧑 멤버 탭의 가입/잔류/이탈이
  이 방식입니다. 나간 시점은 정확히 알 수 없어 "마지막 활동일"로
  대신합니다.

### 닉네임 변경 이력 — ⚠️ 우회

- **하고 싶은 것:** 닉네임을 바꾼 사람의 과거 활동을 이어 붙이기.
- **왜 안 되나:** 소모임은 **현재 닉네임만** 알려 줍니다.
- **앱은 대신:** 사람마다 붙는 **고유번호**로 매칭하기 때문에, 닉네임을
  바꿔도 실명·보정·활동 기록이 자동으로 따라갑니다. 다만 후기 **본문에
  글자로 적힌** 옛 닉네임까지는 자동으로 잇지 못하므로, 그런 경우는
  `후기이름매핑`에서 한 번 지정해 주면 됩니다.

## 12. 부록 — 소모임 연동 명세 (기술 참고)

> 🔧 **이 장은 기술 참고 자료입니다.** 일반 사용자는 읽지 않아도 됩니다.
> 앱이 소모임에서 데이터를 받아오는 방식을 기록해 둔 것으로, 앞 장
> "할 수 없는 것"의 근거이기도 합니다.

### 공통 규칙

- 요청은 모두 소모임 서버(`www.somoim.co.kr`)에 JSON 형식으로 보냅니다.
  별도 로그인 없이 모임 고유번호(`gid`)로 조회합니다.
- 목록은 **최신 → 과거** 순서로 한 번에 20건씩 옵니다. 다음 페이지는
  마지막 항목의 시각(`s_t`)을 커서로 넘겨 받아옵니다. 앱은 최대
  200페이지까지만 요청합니다(수집 기간이 아주 길면 여기에 걸릴 수 있어,
  화면에서 "나눠서 수집하세요"라고 안내합니다).
- 시각 값은 소모임 자체 기준의 숫자로 옵니다(일반적인 컴퓨터 시각에서
  10억 초를 뺀 값). 앱이 날짜로 변환해 씁니다.
- 대상 기간보다 오래된 글에 닿으면 수집을 조기 종료합니다. 출사 공지는
  작성일이 출사일보다 훨씬 앞설 수 있어 **12개월 여유**를 두고 더
  거슬러 받은 뒤 출사일 기준으로 거릅니다.

### 게시글 목록 (`/api/articles`)

요청: `gid`(모임), `wql=20`(페이지 크기), `s_t`(페이지 커서),
`cat`(선택 — `J`를 주면 가입인사만 서버에서 걸러 줌).
응답: `cs`(글 목록), `eof`(끝 표시).

| 필드 | 뜻 | 앱에서의 쓰임 |
|---|---|---|
| `id` | 글 고유번호 | 모든 저장·보정의 열쇠 |
| `at` | 제목 | 카테고리 `[태그]`·취소(펑)·출사일 추출 |
| `c` | 본문 | 참석자·출사일 추출 — **일정 길이에서 잘려서 옴** |
| `w_t` | 작성 시각 | 작성일. 값이 `2000000000`이면 고정(공지)글이라 `ot`를 대신 사용 |
| `ot` | 원 작성 시각 | 고정글의 실제 작성일 |
| `cat` | 글 종류 | `A` 공지 · `E` 후기 · `J` 가입인사 |
| `wn` / `wid` | 작성자 닉네임 / 고유번호 | 표시 / 멤버 매칭(닉네임 변경에도 안정) |
| `lc` / `rn` | 좋아요 수 / 댓글 수 | 인기 집계 — **개수만, 내용·명단 없음** |
| `ic` | 첨부 사진 개수 | **개수만 — 링크가 없어 글↔사진 연결 불가** |

### 사진 목록 (`/api/photos`)

요청: `gid`, `wql=20`, `s_t`. 응답: `ps`(사진 목록).

| 필드 | 뜻 | 앱에서의 쓰임 |
|---|---|---|
| `id` | 사진 고유번호 | 아래 주소 규칙의 재료 |
| `w_t` | 올린 시각 | 월별 집계 |
| `wn` / `wid` | 올린 사람 | 업로더 집계 |
| `lc` / `rn` | 좋아요 수 / 댓글 수 | 인기 / **테마사진 추정**(댓글 있음 = 참여) |

응답에 사진 주소는 없고, 고유번호로 규칙에 따라 만들어 씁니다:
`https://d3vo2hyhx9t76k.cloudfront.net/{id}.png` (뒤에 `m`·`s`·`n`을
붙이면 중간·작은·미리보기 크기). **어느 게시글의 사진인지는 응답에
없습니다.**

### 멤버 목록 (`/api/group`)

요청: `gid`. 응답: `m`(멤버 목록). 페이지 없이 한 번에 옵니다.

| 필드 | 뜻 | 앱에서의 쓰임 |
|---|---|---|
| `mid` | 멤버 고유번호 | 실명 명단·활동 매칭의 열쇠 |
| `mn` | 현재 닉네임 | 표시·본문 이름 매칭 |
| `ban` | `N` 활성 / `Y` 강퇴 | 활성만 집계. **자발적 탈퇴자는 목록에서 사라져 흔적이 없음** |
| `i_m` | 운영진 여부 | 멤버 탭 통계 |
| `j_t` / `v_t` | 가입 / 마지막 방문 시각 | 정착·휴면 분석 |
| `os` / `push` | 기기 / 알림 설정 | 멤버 탭 통계 |

### 이 명세가 말해 주는 것

위 표에 **없는 것**이 곧 앞 장의 "할 수 없는 것" 목록입니다 — 본문 전문,
댓글 내용, 좋아요 명단, 글↔사진 연결 고리, 탈퇴 기록, 닉네임 이력.
소모임이 주는 데이터가 달라지지 않는 한 이 한계는 앱을 고쳐서 넘을 수
없고, 그래서 이 앱은 **사람의 보정을 일급 기능**으로 설계했습니다.
